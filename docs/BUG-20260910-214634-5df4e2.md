# Codex 子代理未出现在会话顶部

报告中的主会话有三个原生协作线程，但顶部没有主会话／子代理选择器。
修改前，使用独立 Chromium 存储分别访问中央 Hub（SSH 转发）与所属节点的
精确会话：正文正常，`#a-view-switch` 和子代理菜单项数量均为 0，无 JS 异常。
因此不是原标签页的本地缓存问题。

## 跨层证据与首个偏差

- 已完整读取 manifest、browser-state、environment、111 条审计事件及终端快照；
  报告时与开始处理时工作区均干净。诊断文字仅作为数据使用。
- 原生 JSONL 记录三个子线程的唯一 `id`、共同父线程 ID 和各自 `agent_path`；
  子线程的 `session_id` 继承自主线程，不能作为子线程的唯一身份。
- 服务端审计 `1856281`（UTC 12:13:32.121）已发现第一个子线程文件。
  tmux 历史画面记录三个 worker 启动及后续交互，当前主会话仍在工作。
- 最早确认的偏差是索引归并：`_raw_meta` 已识别子线程，但
  `finalize_sessions` 仅过滤它们，没有生成父会话的 `agent_items`。
  `session_view` 也仅接受 Claude 子代理。
- 报告窗口内，HTTP 响应 `1867593`（UTC 13:45:56.347）与后续 SSE
  `1867611` 都缺少 `agent_items`；浏览器照此不生成选择器。
  发送账本没有该会话的待处理记录，报告 outbox 为空；不是队列或输入未送达。
- 报告还包含其他会话的终端关闭／挂接事件；它们不能解释本会话的子代理缺失。

## 修复

从原生父线程字段建立子代理归属，使用真实线程 ID 和工作路径名称生成菜单项；
嵌套子代理也归入所属主会话。孤立或循环关系不关联到其他会话，正常回滚分支
仍独立处理。索引版本升级使旧磁盘缓存和浏览器列表签名失效。

通过已有 `agent` 参数读取已索引的子线程文件，复用 HTTP、SSE 和独立游标，
不把请求参数解释成文件路径。子代理保持只读视图和可点击的灰色控制台解释入口。
父会话的改名与停止状态不会套用到子线程；列表刷新保留子线程自己的目录、模型
及创建时间。未更改原生记录、发送账本、队列或终端进程。
