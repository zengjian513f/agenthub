# 回复中的链接与文件操作

## 显示规则

只有括号内的目标参与链接化，说明文字保持普通文本。例如
`说明 (output/report.pdf)` 只链接 `output/report.pdf`。
不重写 Markdown 链接：`[说明](<output/report.pdf> "标题")` 保留原有文字、
标点、空格、方括号、尖括号和可选标题，仅包裹原有目标路径。不会新增任何括号或尖括号。
显示相对路径时仍保留原文，解析得到的绝对路径放在悬浮提示
和“复制绝对路径”中，不用绝对路径替换回复文字。

代码块不参与链接化。文件名或 URL 自带的括号属于目标的一部分。
缺失、歧义、无法确认的文件引用保持可读的普通文本。

## 目标类型与动作

| 目标 | 网页点击 | 右键动作 |
| --- | --- | --- |
| 节点文件 | 经会话授权的文件接口查看；不能安全内联的内容作为文本或附件 | 复制文本、复制节点绝对路径、本地打开、本地打开目录、下载 |
| 节点目录 | 有数量上限的目录列表 | 复制文本、复制节点绝对路径、本地打开、本地打开目录；禁用下载 |
| HTTP / HTTPS | 浏览器打开原始目标 URL | 保留浏览器原生菜单，不套用文件菜单 |
| `file:` | 不自动链接 | 浏览器电脑上的路径不能通过节点的文件存在性检查来确认 |
| 其他协议 | 不自动链接 | 后续按协议逐一支持，不将未知协议作为路径或 HTTP 处理 |

下载是保存文件到浏览器电脑，不等于调用本地应用打开文件。
当前内联文件读取仍有 32 MiB 上限，显式下载采用流式传输。
目录不会隐式打包下载，也不会提供任意路径浏览接口。

## 后端与前端边界

后端只解析在选定会话中出现过的引用，结合该会话工作目录、已记录的完整路径
和实际文件系统确定目标；不递归搜索磁盘，不猜测同名文件。
批量解析接口返回 `ref`、`path`、`kind`（`file` 或 `directory`）及节点标识。
前端依据确认后的类型提供动作，不通过扩展名推断目录或文件。
旧标签页仍可读取兼容的 `resolved` 字段；未知类型不启用下载。

点击和下载时后端再次校验；解析完成后文件被删除等情况应返回明确错误。
Hub 只路由到所属节点，不能将引用文字当作协议字段改写。

## 浏览器电脑上的打开动作

“本地”指浏览器所在电脑。节点上的绝对路径不代表浏览器电脑上的路径。
首次点击本地打开会显示本机助手配置界面。配对成功后，同一页面内后续点击直接打开。
助手文件为 `agenthub/static/desktop-helper.py`，也可在该界面下载；它不在节点服务中启动。

助手使用 Python 3.10 或更新版本，支持 Windows 默认应用、macOS `open` 和 Linux
`xdg-open`。用户在浏览器电脑配置文件访问方式：

- 已挂载或同步：按节点标识和远端目录前缀配置本地目录映射，客户端再次确认
  映射后的路径存在、类型相符，再调用默认应用或文件管理器。
- 未挂载：使用独立的“下载”动作保存文件后手动打开。本地打开会提示映射不可用；
  不会自动下载文件或创建虚假的本地目录。

文件的“本地打开目录”打开其本地父目录；目录的该动作打开目录自身。
复制绝对路径始终复制节点路径，不悄悄改成客户端映射路径。
客户端接入失败需要可见反馈，不能退回到节点执行打开命令。
本机接入程序或浏览器扩展只接受约定的类型和动作，不接受任意 shell 命令。

首次启动示例（替换为自己的网页来源、节点 ID 和目录）：

```sh
python desktop-helper.py --origin "https://hub.example.com" --node "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" --remote-root "/work/project" --local-root "/mnt/project"
```

Windows 的本地目录可以是盘符路径或已挂载的共享目录。再次启动只需
`python desktop-helper.py`。配置和随机配对码保存在用户目录的 `.agenthub-desktop.json`，
不会进入仓库；多个映射按最具体的远端目录匹配。停止助手使用 Ctrl+C。

助手只监听 `127.0.0.1:18711`，校验 Host、网页 Origin 和配对码。
请求携带节点 ID、节点绝对路径、目标类型和固定动作；本地解析拒绝越界和符号链接逃逸。
页面通过 CORS 调用助手，配对码只存于当前页面内存，不进入浏览器持久存储或诊断包。
打开可执行类型需在本地目录中手动操作，不通过网页直接启动。

HTTPS 网页首次连接时浏览器可能要求允许本地网络访问；拒绝、助手未启动、映射错误
均有可见反馈。普通远程 HTTP 页面需要改用 HTTPS，不能绕过浏览器限制。
浏览器行为依据 Chrome 的本地网络访问说明
（https://developer.chrome.com/blog/local-network-access）。

自动回归使用真实 loopback 助手验证 CORS、配对、映射和动作分发，只替换最后一步
系统应用调用，以免测试启动桌面应用。实际客户端的安装、挂载和默认应用仍需在该电脑验证。
