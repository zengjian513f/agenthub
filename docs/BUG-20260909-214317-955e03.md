# 会话下拉菜单被终端遮挡

报告：`BUG-20260909-214317-955e03`。

## 诊断

完整读取 manifest、浏览器快照、环境信息、终端快照，以及 4,630 条审计事件
（包括其中 240 个 JSON 内容载荷），并查看用户截图。
通过 SSH 转发访问中央 Hub 的精确会话，使用报告中的 1698 × 986 视口和终端全屏模式复现。
会话 HTTP/SSE 使用真实服务；终端画面由只读 `capture-pane` 回放到真实 xterm 渲染器，
拦截浏览器的终端控制请求，避免抢占用户正在使用的终端。不启动 CLI。

跨层核对结果：

- 原生 JSONL、解析审计、最后一个 SSE 包及浏览器缓存的游标一致：末尾为 7022797，
  anchor 相同。浏览器显示的末条回复与原生记录及报告终端画面一致。
- 报告 outbox 为空，当前账本也没有该会话的待发项；报告窗口没有该会话的账本变更。
- 审计中的 SSE 断管有后续重连和增量数据，唯一 HTTP 400 来自其他终端的启动目录校验，
  均不能解释菜单遮挡。
- 第一个已证实的偏离发生在浏览器布局：终端全屏让 `#detail` 缩到标题高度，
  它的 `overflow: hidden` 裁掉已正确生成的菜单。6 个菜单项的中心点击命中终端拖动条
  或 xterm，而非菜单。仅提高菜单的 z-index 无法越过祖先的裁切边界。
- 终端自身没有建立独立层叠上下文，内部拖动条还可以越过详情标题的层级。

## 修复及验证

允许菜单溢出 `#detail`，继续由 `.msgs` 管理消息滚动、`#right` 限制页面边界；
为终端建立层叠上下文，将内部控件保留在终端层。手机端现有终端／标题层级仍生效。

中央真实会话加载修订 CSS 后，6 个菜单项全部通过点击命中检查，无脚本错误。
这次检查使用浏览器请求替换 CSS，不代表中央服务已部署。

`python tests/session_menu_e2e.py` 使用隔离 HTTP/SSE/WebSocket fixture：
覆盖独立节点及带路径前缀的 Hub、深浅主题、五种视口、桌面三种终端模式，
检查菜单实际命中、子代理往返切换、消息滚动、终端拖动条和模态弹窗。
原始 CSS 在首个场景稳定得到 6 个失败命中；修订 CSS 全部通过。
